# 臨床工学科 業務お助け君

開発用試作 0.2.0。添付「臨床工学科 業務支援アプリ企画書・改訂第3版」とユーザー依頼に基づく、患者搬送時の酸素・圧縮空気・電源の資源確認ツール。既存React 19 + TypeScript + Vite構成を継承。ユーザーの追加依頼により、Sitesへ本人限定の開発用試作を配置。臨床用の本番配備は未実施。ホームからソースZIPをダウンロード可能。

**実機8機種はすべて調査中。臨床用数値計算は停止。デモは架空専用で臨床使用不可。** 成人V60院内搬送が最初の実機検証対象。治療推奨、機器自動制御、患者の搬送可否判断は実装しない。選択可能であることは計算承認を意味しない。

## 起動

Node.js 22.12以上（今回24.19で実行）、npmを使用。

```sh
npm ci
npm run dev -- --port 5173
```

表示された http://localhost:5173 をブラウザで開く。HTMLをfile://で直接開く運用は対象外。

```sh
npm test
npm run build
npm run test:e2e
```

E2EはChromiumを使用。Linuxで `/usr/bin/chromium` があればそれを使用し、なければ開発環境で `npx playwright install chromium` を実行する。`npm run test:e2e` はビルド済みdistを4173ポートで起動して検証するため、先にbuildを実行。開発サーバーは検証のため全インターフェースをlistenする既存設定を継承。臨床配布設定ではない。

## 実装済み

- 日本語・スマートフォン1列の科内ホーム。臨床確認メニューと架空デモを分離。将来の透析・循環補助・点検は準備中。
- 独立した8プロファイル。SERVO-i/sを別登録、MONNAL T60標準とAdvancedを区別、Evita V600のGS500/PS500を別構成項目、ART-70にV60式を流用しない。全実機の未知構成は未登録。
- 機種別の調査入力、単位、読み取り場所、取得時刻。臨床の必要項目・機種範囲は未確定。FiO₂の物理範囲21〜100%以外の機種上限を創作しない。気道内圧cmH₂O表示は照合待ちの調査欄であり臨床モデルではない。
- 区間追加・削除・名称・5種類の時間、区間別デモ流量、ガス源・電源切替。供給を継続する検査のみ時間へ含める。遅延は各区間へ一度だけ計上。
- 架空登録ボンベの識別番号・残圧・役割・適合。同一番号残量の引継ぎ、二重登録遮断、緊急時留保除外、交換地点・担当役割・手順確認。
- 酸素・空気・電源を別表示。必須資源不明で総合保留、不足は保留中も上部表示。区間開始・消費・終端・切替前不足を表示。
- 入力／設定変更で旧結果とチェックを即時破棄。入力時刻・計算時刻・モデル／プロファイル版・条件・照合状態。
- 出発直前の10項目手動チェック。準備チェック完了と患者の搬送可否を区別。
- 他院搬送の確認項目・区間計画。院内承認を院外承認へ読み替えない。
- 読取専用の管理デモ・承認情報表示。承認変更機能なし、認証なしのブラウザスイッチで承認を成立させない。
- 問い合わせ3分類・報告コピー。送信を偽装しない。連絡先・承認済み代替手順は未登録。

## デモの確認手順

1. ホームの「デモを開始」→「搬送条件へ」→「デモ例を読み込む」。常に「デモ・臨床使用不可」を表示。
2. 内容は架空の往復2区間、酸素・空気各1本、固定負荷電源。例読み込みによるデモ構成・供給の確認は架空条件のみ。出発準備チェックは未完了で開始する。
3. 「デモ資源を再評価する」。予定28分、遅延込み30分。酸素190 Lに対して必要150 L、空気190 Lに対して90 L、電源60分に対して30分。
4. 区間残量を開くと酸素の2区間目開始90 L、終端40 L。同じボンベを毎区間満量にしない。
5. 入力へ戻り酸素ボンベ残圧を1 MPa、電源時間を空欄にして再評価。総合は判定保留でも酸素140 L不足を表示。
6. 緊急時留保へ役割変更すると通常計画へ合算されない。交換用は地点・担当・手順確認が必要。
7. 出発前チェックを手動で付けた後に時間を変更。旧結果とチェックが消える。「設定が変わった」でも同様。
8. ホームから実機確認画面を新規開始。デモ値が引き継がれない。Airvo 2は酸素添加流量・総流量・表示酸素濃度の入力へ切り替わる。どの実機でも結果は保留。

デモの理想ガス換算（内容積2 L、留保0.5 MPa、基準圧0.1 MPa、上限15 MPa）と固定負荷モデルは、開発用の架空設定であり実機の係数ではない。供給元換算表の代替にしない。デモの内部精度は保持し、表示持続時間・残量は0.1単位切捨て、必要量・不足は0.1単位切上げ。全資源の区間条件が異なるため総合持続時間は今回算出しない。

## 構成と拡張

```
src/core/                   共通型・入力検証・無効化・表示丸め
src/profiles/               機種別入力・構成・出典・承認情報
src/modules/index.ts        業務モジュール一覧
src/modules/transport/      区間別資源エンジン・架空モデル
src/validation/             独立参照値に基づくテスト
src/App.tsx                 画面・セッション状態
src/styles.css              レスポンシブ・フォーカス
```

新機種はprofilesへ独立IDを追加し、必要入力・読み取り場所・単位・構成ID・ソフト版・回路・付属品・供給系・電源・適用／対象外条件・出典版頁・検証記録・承認者日付期限を仕様化。同じ承認物理モデルならmodelIdを再利用し設定へ追加できるよう型を分離。異なるモデルなら専用の計算実装・独立参照試験が必要。現段階で登録済みモデルはfictional-direct-v1のみ。実機承認基盤とモデルディスパッチは将来実装し、初期版の強制臨床遮断を単なるブラウザ設定で解除しない。

新業務はmodulesの一覧に追加し、業務専用ディレクトリで入出力・エンジン・テストを管理。現UIは呼吸搬送のみ実装しているため、新業務の画面ルートも追加する。用途・利用者・結果誤りの影響・根拠・試験方法・責任者・保守計画を揃えて審査する。

## 情報管理・配布

患者名・患者ID・利用者名の入力欄なし。構成・モデル・アプリ版のみソースで永続管理。変動入力・調査値・報告・チェックはReactメモリ内のみ。localStorage/sessionStorage/URL保存・アクセス解析・外部ログ送信なし。再読込み・タブ終了・新しい搬送開始で入力を消去する。入力の相談欄にも個人情報を入れない運用が必要。入力値を含む記録ファイル・画像送信は実装していない。

PWA・Service Worker・オフライン配布・自動公開は無効。旧版で使ったブラウザには旧Service Workerが残る可能性があるため、開発確認には新しいブラウザプロファイル／新しいoriginを使用する。院内配布する場合は情報システム部門が旧キャッシュ消去・新版確認を含め管理し、旧originへの上書きだけで停止通知が届くと扱わない。旧版へ戻す運用は承認条件の確認が必須。

## 臨床公開前の条件

コード監査・国内資料確認・独立参照計算・校正測定器とテスト肺による実機試験を実施。V60成人院内の限定構成から検証する。測定ばらつきと不確かさを含む消費上側評価、危険側の過小消費／過大持続時間の合格幅は測定設備と院内承認を要する未確定事項。企画書の試験回数案を実施済みと扱わない。全8機種、院外、異なる回路・モードへ外挿しない。

CE責任者・機器担当CE・医師・看護師・情報システム部門が役割に応じて監査・実機試験・利用者評価・教育・限定試行・承認・配布を実施。3分操作目標の利用者評価は未実施。実機精度、搬送可否、臨床使用準備完了をソフトウェアテストで証明しない。医療機器該当性は免責文で判断せず、用途・機能・誤結果の影響を院内担当部門・専門窓口が確認する。

## 重大不具合の対応

1. 影響するモデル・プロファイルを停止。現在の初期版では全実機計算が既に停止している。将来は承認サービスと配布版双方で停止し、既存結果を破棄する。
2. 院内連絡系統で利用中止を周知。連絡先未提供のため本試作から送信しない。オフライン端末へ即時通知できると保証しない。
3. 影響版・構成・条件・時刻と既存結果の扱いを記録。承認済みの独立代替手順を配布し、最新値と別担当者で照合。資料がない場合は機器担当CE・搬送担当医へ確認。
4. 原因修正、独立参照テスト、影響条件の実機再検証、院内再承認を行う。
5. 復帰先の版も現行承認・範囲・期限を確認。単に旧版へ戻すだけで停止を解除しない。旧キャッシュが停止版を復活させない配布手順を確認してから版復帰する。

テスト実行結果は `docs/TEST-RESULTS.md`。スクリーンショットはデモのUI確認資料であり実機検証記録ではない。

## 簡潔な操作画面（0.3.0）
1年目ME向けに、時間の追加項目・機器表示値・供給圧・結果数量・版情報を詳細欄に整理しました。結果の上部に次の行動を表示し、出発前確認は設定・ガス・電源・到着/交換・最終確認の5項目にまとめています。各確認は手動で行い、入力変更時にすべて解除します。今回のUI改訂は院内承認や実機試験を完了条件としません。実機の未確認消費式を作成したり、数値の搬送可否判定を追加したりはしていません。ソフトウェア試験と臨床検証は別です。

## 画面の作り直し（0.4.0）
添付V60--main.zipの項目構成を基準に、単一画面へ作り直しました。V60の主要入力は残圧・FiO₂・MinVent・Total Leak・搬送予定時間です。実機の値は記録/照合用であり、未確認の酸素消費式には代入しません。結果と出発前確認は入力の下に表示します。旧サイドナビゲーション・段階別画面を廃止しました。デモは「デモを試す」→「デモ例を読み込む」→「デモ結果を見る」で確認できます。検査/待機などは詳細欄で変更できます。
